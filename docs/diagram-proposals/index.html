📐 DS 전체 엔티티 다이어그램 — 4가지 제안

사용자 참조 이미지 스타일을 4가지 변주로 구현 — 어느 방향으로 통일할지 검토용
요구 사항:
  1. 모든 CD viewer 의 다이어그램 / Diagram 섹션을 일관된 한 가지 스타일로 통일.
  2. DS 의 전체 엔티티 구조를 한 장에 표현 (Project · DsSystem · Flow · Work · Call · ApiCall · ApiDef · ArrowWork · ArrowCall · TAG · TokenSpec).
  3. 현재 CD 페이지에 해당하는 엔티티가 어디인지 하이라이트 + 그 동작 특성을 보충 설명.

아래 4가지 모두 "Work" 엔티티가 강조된 상태로 표시. 다른 CD 페이지에서는 동일 다이어그램에서 강조 위치만 바뀜.

제안 1 ⭐ 재설계 v3 3D Isometric — Active ⇄ Passive · Tag Pair 신호 전달

사용자 참조 이미지 스타일을 충실히 재현하면서, 두 DsSystem (Active + Passive) 사이의 Tag Pair 신호 전달(Duality Case 4)을 추가로 묘사.

  • Active DsSystem (좌측, 시안톤 wireframe) = 정식 isometric 3D 박스. 12개 모서리 (가시: 실선, 은면: 점선). Flow ⊃ Work★ ⊃ Call ⊃ ApiCall + Call₂ + Work₂ + WorkArrow + CallArrow 모두 포함.
  • Passive DsSystem (우측, 황금톤 wireframe) = 동일한 isometric 스타일이지만 더 작은 크기 + 색상 차별화 (cyan vs amber). Device/Passive 임을 시각적으로 즉시 구분.
  • Tag Pair Bus = Active 우측 Write Tag (OutTag) ⟶ physical bus ⟶ Passive 좌측 Read Tag (RxTag) ⟶ ApiDef ⟶ Passive 내부 Work. 1:1 paired physical address (예: M001).
  • ApiDef = 5-point chevron flag — Active 좌측 2개 (자체 노출 API), Passive 좌측 1개 (Active 호출 진입점).
  • TAG 피라미드 = 4면 wireframe (좌하단 외부) + ApiDef 로 가는 binding 곡선.
  • 강조: Work 가 빨간색 + glow filter. 다른 CD 페이지에서는 강조 위치만 변경 (예: Call CD 페이지에서는 Call₁ 이 빨간색).
강조 엔티티 (현재 CD) 시스템·컨테이너 WorkArrow CallArrow 경계 노드 (ApiDef·TAG)
✅ 장점
  • 사용자 참조 이미지와 거의 동일 스타일
  • 3D 깊이감으로 시각 임팩트 높음
  • 다크 배경이 기술문서 톤과 잘 어울림
⚠️ 단점
  • SVG 라인 수 많음 (~80줄/CD)
  • 3D perspective 좌표 계산 복잡
  • 인쇄·고대비 모드에서 가독성 저하 가능
🔧 구현
  • 공통 SVG 함수 1개 + highlight=<Entity> 인자
  • 각 entity 별 SVG 좌표 dict 1회 정의 → 재사용
  • 강조: glow filter + 빨간색 채움

제안 2 2D Concentric — 마트료시카 중첩

밝은 배경 + 색상별 stroke로 동심 구조를 평면적으로 표현. Project ⊃ DsSystem ⊃ Flow ⊃ Work ⊃ Call ⊃ ApiCall 을 6단 중첩 박스로 표시. ApiDef 는 DsSystem 우측 경계의 hexagon 노치, TAG 는 좌측 별도 박스. WorkArrow / CallArrow 는 같은 레벨 내부에서 화살표.

강조 엔티티 (현재 CD) Project / ApiDef DsSystem Flow / WorkArrow Call ApiCall / CallArrow
✅ 장점
  • 위계 (containment) 가 시각적으로 명확
  • SVG 코드 단순, 유지보수 쉬움
  • 인쇄·고대비 모드 가독성 양호
  • 각 엔티티가 색상 코드로 즉시 식별
⚠️ 단점
  • 참조 이미지 분위기와 다소 거리
  • 평면적 — 임팩트 약함
  • 3D 박스의 "공간감" 없음
🔧 구현
  • 공통 SVG 1개 + 강조 ID 변경
  • ~50줄/CD
  • 강조: stroke-width 2→3 + 빨간 채움 + glow

제안 3 Graph Network — 관계 중심

엔티티를 노드로, 관계를 엣지로 표현. 위계보다 관계 종류(부모-자식 / 참조 / Arrow / Tag binding) 를 강조. 강조 엔티티는 노드 크기·색채 ↑.

✅ 장점
  • 관계 종류가 시각적으로 분리 (실선/점선/색상)
  • Project, TokenSpec, ArrowWork, ArrowCall 등 모든 엔티티가 한눈에
  • 관계 중심 CD (ArrowWork, ApiCall) 강조에 유리
⚠️ 단점
  • 위계 (containment) 가 약함
  • 참조 이미지와 가장 멀음
  • 엣지가 많아 시각적으로 복잡
  • 레이아웃 결정 어려움
🔧 구현
  • ~70줄/CD (노드 + 엣지 + 범례)
  • 강조 노드 1개만 빨간 채움
  • 관계 미강조 노드는 점선 stroke

제안 4 ⭐ 추천 Hybrid — 참조 이미지 절충 (2D + 경계 노치 + 약한 3D)

제안 1 (3D Isometric) 의 시각 임팩트와 제안 2 (2D 마트료시카) 의 단순성을 절충. DsSystem 은 평면 박스이지만 그림자(box-shadow filter)로 약한 3D 느낌. ApiDef 는 좌·우 경계의 화살표 노치로 돌출. TAG 는 좌하단 외부 피라미드. Flow ⊃ Work ⊃ Call ⊃ ApiCall 안쪽 중첩. WorkArrow / CallArrow 는 색 화살표.

→ 사용자 참조 이미지의 핵심 (3D 박스 + 경계 노치 + 피라미드 TAG) 을 유지하면서 SVG 코드를 단순화.

강조 엔티티 (현재 CD) 시스템·컨테이너 WorkArrow CallArrow 경계 노드 (ApiDef·TAG)
✅ 장점
  • 참조 이미지 분위기 90% 재현
  • SVG 코드 단순 (~60줄/CD)
  • 11 entity + 2 arrow + 1 tag 모두 한 장에
  • 강조 엔티티는 빨간 glow 로 즉시 식별
  • 인쇄·고대비 모드 OK (다크 배경 옵션)
⚠️ 단점
  • 완전한 isometric 3D 는 아님 (그림자만 사용)
  • Project / TokenSpec 은 별도 표현 필요 (외곽 라벨)
🔧 구현
  • 공통 함수 1개 + highlight=<Entity> 인자
  • 각 엔티티별 좌표 dict 1회 → 재사용
  • 강조: fill="#cf222e" + glow filter + ★ 배지
  • SM/Sim CD 는 다른 다이어그램 (별도)

제안 4 (Hybrid) 가 사용자 참조 이미지의 핵심 (3D 분위기 + 경계 노치 + 피라미드 TAG) 을 살리면서 SVG 코드를 단순하게 유지할 수 있어 가장 균형이 좋습니다. 다만 사용자가 더 강한 3D 임팩트를 원하시면 제안 1 도 충분히 구현 가능합니다.

🤔 고려 사항

  • SM/Sim CD 의 다이어그램은 본 다이어그램과 별개 (서로 다른 추상 — SubmodelElement Tree, KPI 산식 등). entity 11 개 CD 만 통일.
  • 강조 엔티티가 ArrowWork / ArrowCall 일 때는 화살표 자체에 glow 적용.
  • ApiDef / ApiCall / TAG / TokenSpec 의 강조 표현은 노치/피라미드 자체를 빨간색으로 변경.
  • Project 강조 시 외곽 점선 사각형을 빨간색으로 변경 (또는 별도 wide-canvas 다이어그램으로).
